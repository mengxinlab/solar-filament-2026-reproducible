# V3 U-Net 失败诊断：在已存预测上定位，不增加训练

日期：2026-10-30。类型：**same-family analysis / provisional causal interpretation**。
本报告读取冻结 v3 开发折 0/1/2 的已有 OOF 概率图、预测 CSV、评分明细和训练日志；
原始图及官方多边形仅检查每折 6 张预先等日期间隔选取的图（共 18 张，155 个标注实例）。
没有加载模型、运行推理、重算 PQ、训练新模型、读取测试标签，或分析 fold 3 的标签。
V3 的 49 张时间外 holdout 维持一次性冻结评估用途。

原始证据：

- `p2_unet_diagnosis.json`：折级概率、训练预算、采样覆盖、已存候选计数和局限。
- `p2_probability_per_image.csv`：全部 658 张开发图的已有概率图统计。
- `p2_prespecified_samples.json`：查看像素/标签内容前冻结的 18 张图 ID。
- `p2_sample_image_diagnostics.csv`、`p2_sample_instance_scales.csv`：样本级标签、尺度和归一化证据。
- `p2_fold0_example.png`、`p2_fold1_example.png`、`p2_fold2_example.png`：原图、官方目标叠加与固定 [0,1] 范围的 OOF 概率示例。
- 源程序：`scripts/diagnose_v3_unet.py`；它不改变 `src/solarseg/` 和 v3 原始结果。

## 1. 两折没有匹配的直接机制是预测响应过低

下表的 TP/FP/FN/PQ直接读取 v3 已保存评分，不是重新评价。

| 开发折 | 图数 | 图像最大概率的中位数 / 全折最大值 | p>0.3 的全帧像素比例 | 纯 U-Net t=0.6 实例数 | TP / FP / FN（t=0.6） | PQ |
|---|---:|---:|---:|---:|---:|---:|
| 0：2011–2013 | 279 | 0.4011 / 0.5034 | 0.01761% | 0 | 0 / 0 / 3731 | 0 |
| 1：2014–2016 | 268 | 0.1318 / 0.1547 | 0% | 0 | 0 / 0 / 3699 | 0 |
| 2：2017–2019 | 111 | 1.0000 / 1.0000 | 0.23881% | 381 | 129 / 527 / 365 | 0.137395 |

**已证事实：** fold 1 的全部概率图连最低预设阈值 0.3 都达不到；全部纯 U-Net 配置因此没有实例。
fold 0 的最大值低于最终纯 U-Net 候选阈值 0.6，故该配置也必然没有实例。
这是阈值化之前已经存在的低响应问题，不是 PQ 匹配器把正常实例清空。
float16 保存和 512→2048→512 插值会影响临界边界，但不足以解释 0.1547 与 0.3 的巨大间隔。

也不能把问题简化为“阈值选高了”：fold 0 在原先预定的 t=0.3 下仍只有
6 TP、201 FP、3725 FN，124 个预测实例散布在 89 张图上，PQ 仅 0.001670。
t=0.45 时仅剩两个预测实例且都未匹配；增大 closing radius 从 1 到 3 未解决该问题。
fold 2 已能产生高响应，但其 t=0.6 仍有 527 FP 和 365 FN，说明实例质量也不理想。

## 2. 分辨率和正负像素预算确有结构性问题

训练源图是 2048×2048；v3将整张图和共识目标降到512×512，线尺度损失4倍。
在155个预选实例上，距离变换局部脊宽的折内中位数约为9.30、8.55、7.93个原图像素，
相当于512图上2.32、2.14、1.98像素；最细样本约0.96个低分辨率像素。
该宽度是离散距离变换的描述性尺度，不是所有barb宽度的精确测量或全数据总体估计。

155个实例中，17个在512图上阈值0.5后的面积少于25像素。
25个低分辨率像素对应400个原图像素，正好是v3神经后处理的最小面积量级。
这些实例未必被所有实际预测过滤掉，但说明整图缩小和面积阈值共同压缩细小结构的空间。
软面积通过area-resize大体保留，不等于形状、可分辨细线和硬阈值面积也被保留。
将512输出再插值成2048只恢复尺寸，不恢复丢失的形态信息。

| 折 | 6张样本的平均软目标正像素比例（全帧） | 样本前景平均预测概率 | 盘内背景平均预测概率 |
|---|---:|---:|---:|
| 0 | 0.3108% | 0.0897 | 0.0289 |
| 1 | 0.3369% | 0.0366 | 0.0247 |
| 2 | 0.0872% | 0.3870 | 0.0043 |

从零训练的小U-Net以整张图为训练样本，BCE未做正类权重，且没有前景中心crop或实例均衡采样；
全图大多数像素是背景/盘外区域。fold 1虽有轻微前景响应，仍与背景较近。
这些是背景主导优化和低置信度解的直接证据，但**不是已完成的因果消融**。
fold 2的样本正像素更稀少却学到了高响应，故仅以“类别不平衡”无法单独解释折间差异。

## 3. 没有找到标签读取为空或几何错位的证据

对18张图，直接从对应官方COCO多边形重建：每annotator内实例union，独立annotator间平均，
area-resize到512。与已缓存训练目标的最大绝对误差为0.001960814，等于uint8量化半步。
目标与源图用同一image_id关联，训练代码对图像和目标应用相同rot90与水平翻转。
因此，本次样本及静态代码证据不支持“所有标签为空”“标签ID索引错误”或“增强只变换一侧”。
这不是对全部训练像素的无限制正确性保证。

共识目标是软概率：仅一个annotator支持的三人区域，其目标为1/3。
若模型校准到该目标，0.6阈值会排除这类区域；官方则仍分别按每个annotator评分。
这存在目标与实例级阈值的语义张力，应在开发数据上明确处理；不能据此改写官方评价。

## 4. 没有太阳盘和limb归一化；原始亮度不是局部丝状体对比度

v3输入只做 `image/255`，没有limb-darkening correction、盘内背景标准化或局部对比度通道。
18个样本中，中心平均灰度约0.538–0.545，近边缘环约0.425–0.440，
径向亮度差约0.10–0.12；不同位置的绝对亮度并不具有统一的“暗条”语义。
例如fold 0样本前景与全盘背景平均亮度几乎相同（0.4860 vs 0.4829），
这不表示丝状体不暗，而是跨位置平均会被径向梯度混淆。

输入的径向分布确实未处理；limb校正是否提升模型需要受控实验。
不能把该观察宣称为fold 1低响应的唯一已证原因。

## 5. 有限更新、采样方式与随机种子/年代混杂

每折固定8×48=384次优化更新，每次batch4，总共1536次有放回整图抽样。
这不是每个epoch完整遍历训练集。

| 折 | 可用训练图 | 每epoch重建的唯一图数量 | 8个epoch重建总覆盖 | 从未抽中的图 |
|---|---:|---|---:|---:|
| 0 | 375 | 149,150,150,156,152,146,151,146 | 366 | 9 |
| 1 | 379 | 148,145,148,149,144,154,148,148 | 375 | 4 |
| 2 | 540 | 163,153,167,162,156,172,162,162 | 507 | 33 |

这些覆盖数是按已保存seed、num_workers=0和每item的三次NumPy随机draw重建，
不是v3运行时实际写出的采样日志。未读取或执行训练图来重建调度。
fold 1覆盖了375/379张图，故“整图大面积没被抽到”不是主要解释；
每次仅约0.3%的正像素仍是学习预算问题。

fold 0/1最后loss约1.02；fold 2在最后两epoch才由约1.03下降到0.94、0.76并形成高响应。
这与不同优化轨迹一致，不能仅凭下降的训练loss诊断过拟合。
三折同时改变了训练年代、验证年代和seed（20261030/31/32），
不能从这三次运行把seed效应、训练分布和时间域偏移分离。

## 6. 有边界的V4行动

1. **优先修复空间尺度与正像素曝露。** 从原2048图及原COCO目标在相同坐标裁512 patch；
   不能放大旧512目标作为所谓full-resolution训练。固定50%前景中心crop、50%盘内随机crop，
   记录采样ID、正像素比例和前景/背景概率分位数。用预算相同的原始强度crop做第一项对照。
2. **第二项只增加盘内/limb校正。** 同一crop协议、固定seed与更新预算，隔离预处理贡献。
   不同时引入任意新loss、延长训练、换backbone和新后处理，避免无法解释的组合变化。
3. **滑窗推理先融合概率再聚合实例。** 重叠crop在原2048坐标加权融合；不要把每patch的实例
   独立拼接成一串碎片。预先固定面积/连通域规则，用开发折评价TP/FP/FN、时期差异及失败图。
4. **若仍低响应，先处理目标/优化而非扫排行榜阈值。** 增加训练日志中的正类损失和开发前景概率，
   一个小而固定的开发阈值集合只能在开发折使用。不得用首次Public Score扫阈值。
5. **fold 3继续冻结。** 本诊断没有使用它的标签。若后续开发要用，先将它明确改名为开发/诊断集，
   并停止把后续测量称为未见holdout。

目前值得一次小预算、机制明确的高分辨率crop实验；没有证据支持直接投入大规模长训。
V4是否继续应由预先冻结的开发PQ、TP/FP/FN和计算成本决定，而非排行榜搜索。
